# Memory OS AI 4.0.5 — ALPHA publiée

État mis à jour le 2026-10-12 : qualifiée, publiée et basculée par Romain/Claude
le 2026-10-11. SQLite+tâches ensuite activés par un GO séparé sur son installation.
Les fonctionnalités ci-dessous ont été livrées opt-in dans le package ;
les formulations de candidate/qualification séparée décrivent la préparation historique.

- Isolation HOME/XDG/AppData de tous les tests v3/v4 avant collecte ; garde
  contre les écritures Python dans le HOME réel, symlink/dir_fd compris.
  Correctif de callbacks setup v3 qui pouvaient contourner les anciens mocks.
- Templates MCP relayés, configs personnelles privées ; preflight_unavailable /
  upstream_not_ready avant envoi distincts d'un contrat legacy. Aucun rejeu
  automatique des mutations ou résultat incertain.
- Qualification des fichiers applicatifs sur l'entrée MCP sémantique ; SHA strict
  pour les fichiers du dépôt. Changements indépendants de l'application ignorés,
  changement MCP ou fichier invalide bloque.
- S4 opt-in : sauvegarde SQLiteAPI/chiffrement/inventaire, restore privé,
  rapprochement d'oublis depuis l'autorité courante, identité et reçu atomiques,
  rotation/crash matrix, rollback après nouvelles écritures vers JSONL. Sidecars
  de tâches préservés mais inactifs en JSONL ; aucun downgrade implicite perdant.
- L7b opt-in et inactif : tâches open/blocked/done, ownership déclaratif relayé,
  next_action/preuves/résolution, historique immuable, CAS de tâches/blocs avec
  ETags magasin/projet/type/objet/révision et reçu L3 final dans la transaction.
  Stale>14jours sans auto-close ; doublons avertis, importtodo proposé seulement.
- Schéma7 : lookup courant indexé, filtre/tri/limite SQL et keyset. Temps de stale
  figé au curseur, cut du projet/identité/filtres protégés. Cible list50p95<30ms
  à10k ; 0,36ms dans une fixture locale, preuve industrielle séparée.
- SQLite+L7b ouvre sans modèle neural. CRUD/CAS/brief/rollback restent disponibles
  à froid ; ready_work_only et retrieval_ready=false sont explicites. Recherche
  ou ingestion initialise/atteste l'encodeur avant utilisation ; panne du modèle
  n'invalide pas les tâches. Profil historique/cache jamais réattesté artificiellement.
- Ready expose capabilities.policies.write_mode pour la fenêtre d'activation.

Les défauts JSONL, registre inactif, profil auto/MPS/native/batch32 et C4
(scoped_literal,lexical_guard_k3) sont conservés. Aucun téléchargement modèle.
Activation SQLite/tâches, jobs/RPO/destination externe et publication exigent leurs
GOs ; ce package ne promet aucun leaderboard ni qualification industrielle par
ses seules unités. Voir v4/docs/QUALIFY_4_0_5.md.

Incident4.0.4 : sa sdist contenait les tests setup pouvant remplacer des configs
utilisateur ; ne pas exécuter cette ancienne suite sur un HOME réel. 4.0.5 inclut
l'isolation et sa qualification ; aucun incident de bascule n'est imputé au moteur.
