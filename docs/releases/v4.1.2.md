# 4.1.2 — identité du dépôt et du registre, sans changement du moteur

Cette note est figée avant la construction du paquet et y est embarquée : elle décrit un périmètre et
n'annonce aucun résultat. L'état de preuve de chaque cellule n'est écrit ni dans cette note ni dans le paquet :
l'aperçu de l'amorce ne le lit que dans un manifeste P9 local (`--p9-manifest`), non signé, lié à l'empreinte
SHA-256 exacte du wheel, et affiche `non testé` sans lui. Aucun gain mesuré n'est revendiqué. Les évaluations
P-A et P-B n'ont pas été lancées pour la 4.1.2 (dérogation explicite du mainteneur) ; les résultats des
versions antérieures restent ceux de ces versions.

## Contenu

- **Dépôt actif.** `RoaminS/Memory-os-ai` remplace le miroir figé `romainsantoli-web/Memory-os-ai` : URL `Source`
  et `Issues` du paquet, `repository.url` de `server.json`, bandeau du README.
- **Identité au registre MCP.** `io.github.RoaminS/memory-os-ai`, casse comprise (le registre y est sensible),
  dans la ligne `mcp-name` du README et le champ `name` de `server.json`.
- **`server.json` prêt pour le registre.** `publication_ready: true`. C'est une condition de publication, pas un
  résultat : la version n'est publiée que si la porte P10-a passe. Cette porte exige qu'un client MCP (le SDK Python
  officiel) lance la commande du registre,
  `uvx --from memory-os-ai[ops,brief]==4.1.2 memory-os-relay memory-os-ai` (arguments de `server.json` plus
  l'identifiant ajouté par le consommateur), hors ligne et confiné, contre un service jetable, sur macOS arm64 avec
  CPython 3.11. Son résultat ne figure pas dans le manifeste P9 (voir l'erratum ci-dessous).
- **Métadonnées du paquet.** Classifieur `Operating System :: POSIX :: Linux` déclaré ; la prise en charge de
  Linux reste limitée à la cellule Ubuntu 24.04 arm64.
- **Dépôt GitHub.** Fichiers hérités retirés : `requirements_cpu.txt`, `requirements_gpu.txt`, `smithery.yaml`,
  `Dockerfile`, workflow de publication PyPI. La CI GitHub ne fait plus que le lint `ruff` et la recherche de
  secrets **vérifiés** ; la qualification reste locale, par cellule. `docs/DISTRIBUTION.md` et `CONTRIBUTING.md`
  décrivent cet état.
- **Inchangés depuis la 4.1.1.** Récupération (deux profils), schéma SQLite 8, encodeur, cache d'embeddings,
  cellules de plateforme, verrous et manifestes d'artefacts, amorce. Seuls changent dans le code les littéraux
  de version et les messages de refus qui nomment la version courante.

## Limites déclarées

- **Limites de la 4.1.1 reconduites.** Elles restent valables : manifeste P9 non signé, fenêtres de concurrence
  résiduelles, limites du confinement employé sous macOS, durabilité sous Linux établie sur macOS seulement,
  formes de `systemctl show`, amorce et `XDG_CONFIG_HOME` (`docs/releases/v4.1.1.md`).
- **Clients refusés sous Linux.** VS Code, Windsurf et Claude Desktop restent refusés sous Linux
  (`client_unsupported_on_os`). Réévaluation reportée en 4.1.3.
- **Clients réels non qualifiés par la commande du registre.** La porte P10-a emploie le SDK MCP officiel comme
  client. Claude Code, Codex et les autres clients n'ont pas été lancés par la commande du registre.
- **Paquet hérité v3.** Le wheel embarque encore le paquet `memory_os_ai` et sa commande `memory-os-ai-v3`. Ils ne
  sont pas qualifiés (les portes ne passent que la suite v4) et ne sont pas pris en charge. Leur sort sera
  décidé en 4.1.3.
- **Porte P8 non applicable, sur le principe.** Le mainteneur a accepté que la porte P8 soit déclarée non applicable
  si le diff Git ne touche ni le moteur, ni le store, ni la sauvegarde, ni les dépendances, ni la configuration
  d'exécution, ni l'arrêt. La preuve ligne à ligne et son acceptation sont établies après le gel de cette note et
  consignées dans le manifeste P9, pas ici. Si elles manquent, la version n'est pas publiée.
- **Reportés en 4.1.3.** Curseur de `changes.py` (le décodage accepte une écriture base64 non canonique ; aucun
  contournement du MAC du curseur n'a été démontré), lecture WAL en `mode=ro`, cellule Linux x86_64, CI par
  cellule.
- **Recherche de secrets.** Sur un push, la CI ne scanne que les commits poussés ; un résultat vide ne prouve pas
  l'absence de secret.

## Erratum (25 novembre 2026)

Cette note, gelée avant la construction, affirmait que le résultat de P10-a figure dans le manifeste P9 de la Release
GitHub. C'est inexact : le manifeste P9 (`bdac98cb…`) consigne les portes par cellule et ne mentionne ni P10-a ni
P10-c. Les deux résultats (P10-a PASS 30/30 ; P10-c PASS 32/32 avec le wheel téléchargé depuis PyPI) figurent dans le
[complément de preuves](https://github.com/RoaminS/Memory-os-ai/releases/download/v4.1.2/memory-os-ai-4.1.2.proof-complement.md), actif distinct de la Release v4.1.2, avec ses
propres sommes de contrôle. Les deux portes emploient le SDK MCP comme client scripté, pas Claude Code ni Codex. La
description PyPI de la 4.1.2 conserve l'ancienne formulation : une version publiée ne se modifie pas, et la 4.1.2
n'est ni reconstruite ni republiée.
